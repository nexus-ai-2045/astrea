# 星詠みの巫女 アストレア

西洋占星術・数秘術・タロットを使う対話型の AI 占いアプリ。当てにいくのではなく、相談者が自分で考えるための鏡として占術を扱う。

## 概要

生年月日から命式を計算し、相談者自身がタロットの展開法を選び、3 枚の札を自分の手でめくる。そのうえで数往復の対話を経て、統合された鑑定を返す。

**占いは科学ではない。** それを前提に作ってある。

- **計算は正直に。** 星座も数秘もカードも実際に計算・抽選し、結果を改変しない
- **曖昧な当て推量を使わない。** 「現状に不満をお持ちですね」のような、誰にでも
  当てはまる話術を明示的に禁じている。実際の計算結果か、相談者が実際に言った
  ことだけを根拠にする
- **依存させない。** 占いは自分で考えることの代替ではなく、それを強化する道具。
  答えを与えきらず、相談者が考える余地を必ず残す
- **選択に意味を持たせる。** どの展開法で読むかも、どの札から開くかも相談者が決める

このスタンスは文章だけでなく、`src/lib/system-prompt.test.ts` と
`src/lib/tarot-integration.test.ts` でテストとして固定してある。

## できること

出迎え → 生年月日 → 展開法を選ぶ → 3 枚を自分でめくる → 対話 → 本鑑定、という
一連が通る。

### 展開法

3 枚引きのバリエーションから、対話型鑑定に合う 5 種を採用している。

| 名前 | 位置 | 向く相談 |
|---|---|---|
| 時の流れ | 過去 / 現在 / 未来 | 漠然とした不安、人生の節目 |
| 現状と道 | 状況 / 障害 / 助言 | 具体的な悩み、決断 |
| 二人の間 | あなた / 相手の気持ち / 関係の行方 | 特定の相手との関係 |
| 分かれ道 | 選択肢A / 選択肢B / 決め手 | 二択で迷っているとき |
| 心と身体 | 心 / 身体 / 魂 | 疲れ、不調 |

アストレアが会話の流れから 3 つを言葉で勧め、相談者は画面の一覧から 1 つ選ぶ。

**位置はめくった順に決まる。左端の札が 1 枚目ではない。** 最初にタップした札が
第 1 の位置になり、タップ前に「次にめくる札が【障害】になります」と予告される。

## 使い方

```bash
npm install
npm run dev
```

LLM 呼び出しはローカルの `claude` CLI を子プロセスとして起動する方式で、
API キーは使わない。CLI の認証が要る。

```bash
claude setup-token   # 1年有効のトークンが出る
export CLAUDE_CODE_OAUTH_TOKEN=...
```

CLI の認証が無い環境でも、file 経由の bridge で UI を通し確認できる。

```bash
FORTUNE_DEV_BRIDGE=1 npm start
```

`.dev-bridge/<sessionId>.NNN.request.md` にプロンプトが書き出されるので、
同じ base 名の `.response.md` を書くとアプリがそれを配信する。

### テスト

```bash
npm test
npx tsc --noEmit
npm run build
```

## 構成

```
src/app/api/fortune/chat/route.ts   SSE ストリーミングの本体
src/lib/claude-cli.ts               claude CLI の起動と env の扱い
src/lib/claude-session.ts           常駐プロセス（起動コストが支配的なため）
src/lib/fortune-engine.ts           西洋占星術・数秘術の計算
src/lib/tarot.ts                    デッキと抽選
src/lib/tarot-spread.ts             展開法の定義と位置ラベルの割り当て
src/lib/opening.ts                  出迎えの定型文（ここだけ LLM を呼ばない）
src/lib/system-prompt.ts            アストレアの人格と対話フロー
src/lib/rate-limit.ts               四層のレート制限
src/lib/db.ts                       セッションと会話の保存
```

設計上、読む価値のあるところ。

**プロンプトは仕様書でもある。** UX を変えたら `system-prompt.ts` も追随させる。
過去に「1 枚選ぶと残りも自動で開く」から「3 枚とも自分でめくる」へ変えたのに
prompt が旧仕様のままで、アストレアが画面と違う説明をした事故がある。

**タロットの出所は 1 つだけ。** 占術エンジンも独自に 3 枚引けるが、鑑定に載せるのは
相談者が画面で見た札だけ。両方載せると「見たカード」と「鑑定の根拠」が食い違う。

**位置の規則が 2 箇所に独立して存在する。** 画面表示 (`labelsByRevealOrder`) と
鑑定プロンプト (`orderByReveal` → `spreadToPromptContext`)。ここが割れると
「障害」と表示した札を鑑定が「助言」として読む。

## 制約と注意

- **占いの結果を根拠に重要な判断をしないこと。** 医療・法律の領域には踏み込まない
- **会話と生年月日はサーバに平文で保存される。** 暗号化も自動削除もない。
  氏名・連絡先などを入力しない前提で作ってある
- 過去の鑑定を別の相談者の参考に混ぜる機能があるが、対象は運用者が中身を読んで
  明示的に許可したセッションだけ。既定では 1 件も許可されていない
- レート制限は四層（IP 窓 20/10分・IP 日次 60・セッション 40 発話・全体日次 500）
- self-host する場合、公開面の前提は Cloudflare 経由で `cf-connecting-ip` が
  付くこと。素の `x-forwarded-for` は偽装できる

信頼境界と脆弱性の報告先は [SECURITY.md](SECURITY.md)、開発の進め方は
[CONTRIBUTING.md](CONTRIBUTING.md)。
